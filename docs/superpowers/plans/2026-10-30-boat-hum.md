# Boat Hum Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Preserve uncommitted work; no branch changes or commits.

**Goal:** A second built-in sound that sequences boat recordings with fractal-modulated crossfades.
**Architecture:** BoatHumEnvelope supplies bounded volume/crossfade shape; BoatHumPlayer owns two Media3 decks, preloading and transitioning by real playback position. Reuse the existing noise math in a shared FractalNoise utility and extend AmbientPlayer to manage both built-ins safely.
**Tech Stack:** Existing Kotlin, Media3, Compose toggles, JUnit/Robolectric; FFmpeg asset processing.
**Spec:** `docs/superpowers/specs/2026-10-30-boat-hum-design.md`

## Global Constraints
- Boat recordings are sequential, with only transition overlap; keep Ocean waves' five-layer behavior.
- New Boat hum toggle supports independent and combined built-in selection; no cross-source mixing.
- Match loudness, soften high frequencies, preserve offline licenses, retain mix headroom.
- Existing break and paused-source semantics remain valid; no new runtime dependencies.

## Review Focus
- Only current deck audible outside a transition; preload does not start itself.
- Slow preparation or buffering cannot finish a fade before incoming audio plays.
- Stop/restart cancels timers/listeners and never resurrects playback.
- Toggling one built-in preserves the other and its focus/routing ownership.
- Combined gain remains bounded during entrances, exits, and selection changes.
